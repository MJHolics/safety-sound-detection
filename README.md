# safety-sound-detection — 현장 소음 속 위험음 인식

산업 현장에서 유리 깨짐·사이렌·화재·경보벨·차량 경적 같은 **위험음**을 소리로 잡을 때, 무엇을 쓰고 어디서 무너지는지 쟀다.
고전 특징(MFCC)·처음부터 학습한 소형 CNN·CLAP 제로샷·CLAP 임베딩 분류를 같은 공식 5-fold에서 비교하고,
**합성 공장 소음과 학습에 한 번도 쓰지 않은 실제 기계음**을 SNR 20/10/0dB로 섞어 위험음을 놓치는 비율과 엣지 비용을 같이 본다.

## ① 목표·이유
카메라가 못 보는 사각지대와 야간에도 소리는 들린다. 그런데 공개 벤치마크 정확도는 조용한 녹음 기준이고, 현장은 기계 소음이 깔려 있다.
"정확도 몇 %"가 아니라 **소음이 깔렸을 때 위험음을 몇 건 놓치는가**를 알고 싶었다.

## ② 상품성
산업안전 관제·스마트팩토리 모니터링에서 마이크는 카메라보다 싸고 설치가 쉽다. 위험음 검출은 놓침(무경보)이 오경보보다 비싸고,
엣지 장비에 올려야 하므로 지연·크기가 함께 중요하다.

## ③ 설계 채용 근거
| 결정 | 이유 |
|---|---|
| ESC-50(2,000클립·50종·공식 5-fold) | 공개·재현 가능, 위험음 후보 클래스 포함. 폴드는 같은 원본 녹음이 갈라지지 않게 나뉘어 있다 |
| 위험음 5종을 **모델을 돌리기 전에** 고정 | glass_breaking·siren·crackling_fire·clock_alarm·car_horn(200클립). 결과를 보고 고르면 유리한 것만 남는다 |
| 실제 기계음(엔진·청소기·세탁기)은 **평가에만** | 학습 증강은 합성 소음만 — 기계음은 처음 보는 소음 유형으로 남긴다. 기계음은 테스트 클립과 다른 폴드에서 가져온다 |
| 모델 4계열 | 고전 기준선(MFCC+로지스틱) · 엣지형 소형 CNN(파라미터 10만) · 텍스트로 클래스를 지정하는 CLAP 제로샷 · CLAP 임베딩+로지스틱 |
| 짝지음 검정 | 같은 2,000클립에 대한 정오를 McNemar로 비교 |

## ④ 성능 비교 (실측, 5-fold 합산 2,000클립)

**50종 정확도**

| 모델 | 깨끗함 | 합성 20dB | 합성 10dB | 합성 0dB | 기계음 20dB | 기계음 10dB | 기계음 0dB |
|---|---:|---:|---:|---:|---:|---:|---:|
| MFCC + 로지스틱 | 0.438 | 0.385 | 0.349 | 0.276 | 0.333 | 0.248 | 0.132 |
| 소형 CNN | 0.720 | 0.644 | 0.548 | 0.351 | 0.600 | 0.448 | 0.215 |
| 소형 CNN + 합성 소음 증강 | 0.723 | 0.723 | 0.723 | 0.685 | 0.637 | 0.488 | 0.229 |
| CLAP 제로샷 | 0.915 | 0.915 | 0.900 | 0.837 | 0.862 | 0.747 | 0.464 |
| CLAP 임베딩 + 로지스틱 | **0.967** | 0.961 | 0.953 | 0.867 | 0.915 | 0.781 | 0.464 |
| CLAP 임베딩 + 로지스틱 + 증강 | 0.965 | 0.960 | 0.961 | 0.940 | **0.916** | **0.793** | **0.506** |

**위험음 200클립 중 놓친 수 (오경보율 = 나머지 1,800클립 중 위험음으로 판정한 비율)**

| 모델 | 깨끗함 | 기계음 10dB | 기계음 0dB | 오경보율(깨끗함 / 기계음 0dB) |
|---|---:|---:|---:|---|
| 소형 CNN | 42 | 102 | 146 | 2.1% / 4.3% |
| 소형 CNN + 증강 | 38 | 88 | 145 | 2.2% / 4.9% |
| CLAP 제로샷 | 1 | **29** | **77** | 0.2% / 1.1% |
| CLAP 임베딩 + 로지스틱 | 1 | 44 | 103 | 0.1% / 0.4% |
| CLAP 임베딩 + 로지스틱 + 증강 | 1 | 37 | 95 | 0.1% / 0.7% |

- **합성 소음으로 증강하면 합성 소음 시험에는 크게 듣고 실제 기계음에는 작게 듣는다.** CNN 10dB에서 합성 +17.5%p(0.548→0.723),
  기계음 +4.0%p(0.448→0.488, 짝지음 155:75, p=1.4e-7). 깨끗한 소리에서는 차이 없음(102:96, p=0.72).
  학습에 쓴 소음 종류로 평가하면 강건성이 크게 부풀려진다.
- **짧은 충격음이 가장 먼저 사라진다.** CNN의 유리 깨짐 재현율은 깨끗할 때 0.925 → 기계음 10dB 0.10 → 0dB 0.025.
  사이렌·경보벨처럼 지속되는 음은 0dB에서도 0.40~0.43이 남았다. 증강도 유리 깨짐은 못 살렸다(0dB 0.00).
- **깨끗한 소리에서는 학습한 CLAP 분류기가 낫지만, 강한 실제 소음에서 위험음은 제로샷이 덜 놓친다.**
  깨끗함 정확도 불일치 126:23(학습 우위, p=2e-18) / 기계음 0dB 정확도는 동률(188:189, p=1.0) /
  기계음 0dB 위험음 검출은 제로샷만 잡은 것 32, 학습만 잡은 것 6(p=2.4e-5), 증강한 학습 분류기와 비교해도 28:10(p=0.005).
  깨끗한 임베딩에 맞춘 결정 경계가 소음으로 이동한 임베딩을 다른 클래스로 보내는 것으로 보인다(원인 분석은 하지 않았다).
- 학습한 특징이 크게 앞선다: MFCC 대비 CNN 695:130(p=5e-94), CNN 대비 CLAP 509:15(p=1e-129). 5-fold 표준편차는 CNN 0.021, CLAP 0.008.

**엣지 비용 (CPU 1스레드, 5초 클립, 전처리 포함, 클립 50개 중앙값)** — `edge_bench.py`

| 모델 | 지연 p50 | 크기 | fold 1 정확도 |
|---|---:|---:|---:|
| MFCC + 로지스틱 | 3.6ms | 파라미터 8,050 | — |
| 소형 CNN, PyTorch | 4.4ms | 파라미터 103,842 | — |
| 소형 CNN, ONNX FP32 | **2.0ms** | 417KB | 0.723 |
| 소형 CNN, ONNX 동적 INT8 | 14.2ms | 115KB | 0.713 (FP32와 일치 95.5%) |
| 소형 CNN, ONNX 정적 INT8(QDQ) | 2.3ms | 120KB | 0.713 (FP32와 일치 98.5%) |
| CLAP 오디오 인코더 | 167ms | 파라미터 2,819만 | — |

- CNN 지연 2ms 중 1.4ms가 log-mel 전처리다. 모델 계산은 1ms도 안 된다.
- **동적 INT8은 7배 느려졌다** — 합성곱을 정수 연산(ConvInteger)으로 바꾼 경로가 CPU에서 느리다. 보정 데이터로 범위를 정하는
  정적 양자화(QDQ, 학습 폴드 log-mel 200개로 보정)로 바꾸니 FP32와 비슷한 속도에 크기 3.5배 축소. 이 크기의 모델에서 INT8의 이득은 속도가 아니라 크기다.
- CLAP은 CNN보다 80배 느리지만 5초 클립을 0.17초에 처리해 CPU 1스레드로도 실시간 30배 여유가 있다.

## ⑤ 교체 기록
- **동적 INT8 → 정적 INT8(QDQ)**: 동적 양자화가 지연을 2.0→14.2ms로 늘린 걸 보고 교체. 2.3ms·120KB·FP32 일치 98.5%.
- **"합성 소음 증강이면 강건해진다" → 처음 보는 소음으로 따로 평가**: 증강 효과를 합성 소음으로만 쟀다면 +17.5%p로 보고했을 것.
- **위험음 판정에 제로샷을 남길 근거**: 학습 분류기가 정확도는 높지만 강한 실제 소음에서 위험음을 더 놓쳐, 둘을 함께 쓰는 설계가 필요하다(미구현).

## ⑥ 에러 대처 기록
- `factory_noise`가 2,048샘플보다 짧은 입력에서 길이가 틀어졌다 — `np.convolve(mode="same")`는 커널이 신호보다 길면 커널 길이를 돌려준다.
  5초 클립에선 안 나는 버그를 단위테스트가 잡았다 → 커널 길이를 입력 길이로 제한.
- 완전 무음 판정이 안 됐다 — 0 신호의 rms가 `sqrt(1e-12)`=정확히 1e-6이라 `< 1e-6`에 안 걸렸다 → `<= 1e-5`. 데이터셋에 완전 무음 클립은 0개라 결과 영향 없음을 확인.
- transformers 5.x에서 `get_text_features`가 텐서가 아니라 출력 객체를 돌려줬다 → `pooler_output`이 forward의 `text_embeds`와 일치함을 확인하고 사용.
- onnxruntime 양자화가 shape inference 중간 파일을 다시 열다 한글 경로(`AI개발`)에서 실패 → ASCII 임시 폴더에서 양자화 후 복사.
- 처음 엣지 벤치는 학습 안 한 CNN으로 INT8 일치율을 쟀다(의미 없음) → 벤치가 fold 1 학습 모델을 저장하고 그걸로 테스트 400클립 정확도를 비교.

## ⑦ 개발 순서
위험음 5종·소음 설계 고정 → 특징 캐시(조건 7 × 2,000클립: MFCC·log-mel·CLAP 임베딩·제로샷 점수) → 5-fold 모델 7종 → 짝지음 검정 → 엣지 벤치 → 양자화 교체.

## 실행
```bash
pip install torch librosa soundfile transformers scikit-learn onnxruntime
# data/ESC-50-master 에 ESC-50 압축 해제(https://github.com/karolpiczak/ESC-50, CC BY-NC — 저장소에 포함하지 않음)
python build_features.py   # cache/<조건>.npz (약 15분, GPU)

```

## 정직한 범위
- **CLAP 수치는 상한일 수 있다**: CLAP 학습 데이터(LAION-Audio-630K)에 Freesound가 포함되고 ESC-50도 Freesound에서 왔다 — 같은 녹음을 봤을 가능성을 배제하지 못했다.
- 소음은 클립 단위 가산 혼합(합성 1종·실제 기계음 3클래스)이다. 실제 현장의 잔향·마이크 거리·여러 소리 동시 발생은 없다.
- ESC-50은 5초 단일 라벨 클립이다. 연속 스트림에서의 탐지 지연·구간 검출은 재지 않았다.
- CNN은 폴드당 시드 1개. 정확도 비교는 폴드 표준편차(0.02)보다 훨씬 큰 차이만 해석했다.
- 위험음 5종은 ESC-50 클래스 중 고른 것이고, 실제 산업 위험음(가스 누출음·베어링 이상음 등)은 없다.
